> 总体架构见 [DEVELOPMENT.md](DEVELOPMENT.md)。

## 1. 坐标系(实机确认)

| 轴 | 含义 | 方向 | 原点 |
|---|---|---|---|
| **X** | 纸带横向 = 音调 | X+ = 向右 | **X0 = 纸带左边缘线**,且是**冲针圆心**位置(不是冲针边缘,无半径补偿) |
| **Y** | 纸带纵向 = 时间 | Y+ = 纸带向前(时间增加) | Y0 = 纸带起点(第一个时间步所在位置) |
| **Z** | 冲针 | 值越大越往下 | Z0 = 最高位 |

因此 G-code 里的 X 值 = **孔圆心到纸带左边缘的距离**,直接写目标值即可。

### Z 三层(重要)

下表是 `MachineParams` 的**代码默认值**;实际使用值由 GUI ⑤ 选定并存进工程(`data/project.json` 的 `z_params`),
**以工程值为准**(生成的 G-code 头注释里会写明本次用的三个高度):

| Z(默认) | 名称 | 什么时候用 |
|---|---|---|
| **0** | **移动高度** | **完全不冲孔时**:G00 首尾定位、最后 100mm 外送带 |
| **4** | **安全高度** | **打孔阶段的所有移动**(行内横移 + 换行送带)+ 冲孔后抬起位 |
| **10** | **工作高度** | 冲孔(G1 压下) |

⇒ 单次冲孔的实际 Z 行程 = `z_work - z_safe`(上表默认值 ⇒ 6mm)。
**当前工程的 `z_params` 是 `{工作 10 / 安全 6 / 移动 0}`** ⇒ 行程 **4mm**,单孔 Z 用时 0.24s。

动作序列(G-code 实际形状,以当前工程值 0/6/10 为例):

```
G0 Z0  →  G0 X0 Y0  →  G0 Z6               ; 首尾在移动高度, 然后降到安全高度
每行:   G1 Y<y> F1000                      ; 换行送带(安全高度)
        每个孔: G0 X<x>                     ; 行内横移(安全高度)
                G1 Z10 F2000
                G4 P0.1
                G1 Z6 F2000                ; 冲孔 → 抬回安全高度
结束:   G0 Z0  →  G1 Y<last+100> F1000     ; 抬到移动高度后外送 100mm
```

> **三个高度可以在 GUI ⑤「打孔 Z 高度」里改**,不必动代码;选定值存进 `data/project.json`
> 的 `z_params`,由 `GET/POST /api/gcode/params` 读写,重启后保留。
> 顺序约束:**移动高度 ≤ 安全高度 ≤ 工作高度**(Z 值越大越往下),后端会校验并拒绝反向值,
> 前端在点「生成打孔 G-code」时也会先应用一次并现场报错。
>
> 行程越短节拍越快:`z_safe` 越大越靠下、行程越小 —— 从默认的 4 改到 6,行程由 6mm 减到 4mm,
> 单孔 Z 用时 0.36s → 0.24s(见 §8),所以"抬高安全高度"会更快,但净空变小,按实际机械取舍。
> 另外,"移动高度" 已由原来只有注释的状态提成正式参数(`z_travel`,取代旧 `z_home`/`move_z`)。

## 2. 纸带几何与列坐标

- 纸带物理宽 **70 mm**;有效音频区 **57.5 mm**;左右空白各 **6.25 mm**(= (70−57.5)/2)。
- 30 个音列按 **edge 模式**分布:第 1 列(col0)与第 30 列(col29)的**孔圆心分别落在有效区两端**:

```
X(col) = 6.25 + col × (57.5 / 29)      # 列距 = 1.982759 mm
col0  = 6.250 mm      (左侧留白 6.25)
col29 = 63.750 mm     (右侧留白 6.25)
```

常用列坐标(便于核对):

| col | X (mm) | col | X (mm) | col | X (mm) |
|---|---|---|---|---|---|
| 0 | 6.250 | 10 | 26.078 | 20 | 45.905 |
| 2 | 10.216 | 12 | 30.043 | 24 | 53.836 |
| 5 | 16.164 | 15 | 36.000 | 26 | 57.802 |
| 8 | 22.112 | 18 | 41.940 | 29 | 63.750 |

> 若以后换成"按 30 等分格中心"的排布,把 `MachineParams.col_mode` 改为 `"center"`
> (列距变为 57.5/30,X(col)=6.25+(col+0.5)×列距)。

## 3. 时间 → Y 换算 —— 孔距才是"音乐"

纸带上的**孔距 = 音长**:一个孔 = 一次拨弦,相邻孔之间的距离就是这段时间。

```
每步时间  step_seconds = 60 / (bpm × steps_per_beat)
孔距      mm_per_step  = step_seconds × feed_mm_s        # feed_mm_s = 16 mm/s
Y(row)    = row × mm_per_step
纸带长度  = 曲目时长(s) × feed_mm_s                      # 与"每拍格数"无关
```

> ### ⚠️ 两个"速度"是两件事
> **八音盒上的实际节奏 = 孔距 ÷ 八音盒走带速度。**
>
> - `feed_mm_s`(默认 **16 mm/s**)= 纸带**几何**:决定孔与孔相距多远,
>   也就是八音盒上听起来多快、**音梳有多少时间复位**(孔太密会来不及重新发声)。
> - `y_feed_mm_min`(默认 **1000 mm/min**,G-code 里的 `F`)= 打孔机送带快慢:
>   **只决定"打孔要打多久",与音乐节奏无关**。
>
> 两者在 2026-09 之前被写成了同一个量(`480 = 8×60`),改一个会连带影响另一个;
> 现在已解耦:改孔距不必动 F,改 F 也不会把曲子变快变慢。

调整历史:`feed_mm_s` 8 → **16 mm/s**(孔距翻倍,解决音梳复位);孔距翻倍后同一首曲子的
纸带长度也翻倍,送带 F 同步 480 → **1000 mm/min**(Y 轴实测值),打孔总耗时才不会翻倍。

示例(当前工程纸带 `Shelter.mid`,经 ③ 量化后 `bpm=98, steps_per_beat=16`):
`step_seconds = 60/(98×16) = 0.038265s` → `mm_per_step = 0.6122mm` → 末步 row 5237 ≈ **3206 mm**
(加上尾部 100mm = 3306mm 纸带)。

> 提高"每拍格数"只改变 Y 的**量化精度**(步长变细、行数变多),纸带总长不变;
> 而改 **BPM 会改变每步孔距**(`mm_per_step = (60/BPM/每拍格数) × feed_mm_s`),
> 太快时孔距过密、音梳来不及复位,需要按 Y 拉伸系数 k 放大纸带(见 §6 用量速算)。

## 4. 路径规划(实现规则)

1. **同排多孔必须停带**:同一 `row` 上多个 `col` = 同一条横线上的和弦,纸带停在对应 Y,
   按 X **依次**冲完该行所有孔,再继续送带。
2. **每行从最近端进入**:比较该行最小/最大列的 X 与当前 X 的远近,选择先冲哪一端,
   冲完不折返(减少空程;实测本曲 X 空移从 959s 降到 683s)。
3. **空行跳过**:只对有孔的行做 `G1 Y…` 定位,其余时间不送带。
4. **移动安全**:打孔阶段的所有移动(行内横移 + 换行送带)都在 Z=安全高度(4);
   冲孔动作走 4 → 10 → 4。完全不冲孔的部分(程序首尾、尾部外送带)抬到移动高度(0)走 G00。
5. **结束不回 Y0**:冲完最后一个孔后抬到移动高度,`G1 Y(last+100mm)` 继续前进 100mm,便于剪下纸带,然后 `M30`。

生成的头注释里会带上:孔数、有孔行数、纸带长度、耗时预估与分解,便于上机前评估。

## 5. 参数表(`MachineParams`,server/gcode.py)

| 参数 | 默认 | 说明 |
|---|---|---|
| `paper_width_mm` | 70.0 | 纸带物理宽度 |
| `audio_width_mm` | 57.5 | 有效音频区宽度 |
| `ncol` | 30 | 音列数 |
| `col_mode` | `edge` | 列分布模式(`edge`/`center`) |
| `feed_mm_s` | **16.0** | 纸带孔距换算(mm/s):孔距 = 八音盒上的音长,**与打孔快慢无关** |
| `z_travel` | **0.0** | 移动高度:完全不冲孔时(G00 首尾/尾部外送带);**GUI ⑤ 可改** |
| `z_safe` | **4.0** | 安全高度:冲孔后抬起 + 打孔阶段的所有移动;**GUI ⑤ 可改** |
| `z_work` | **10.0** | 工作高度:冲孔位;**GUI ⑤ 可改** |
| `z_feed` | 2000.0 | Z 下压/抬起速度(mm/min) |
| `dwell_s` | 0.1 | 冲孔停留(压住时间) |
| `xy_feed` | 3000.0 | X 空移速度(mm/min)。⚠️ **本机 `$110` 上限 2500**,超限会被 GRBL 限速、且注释耗时失真,详见 §7.2 |
| `y_feed_mm_min` | **1000.0** | 打孔机送带 F(mm/min):**只影响打孔耗时,不影响音乐** |
| `y_tail_mm` | 100.0 | 结束后继续前进的距离(便于剪带) |

生成入口:
- GUI **⑤「打孔 Z 高度」**选三个高度(校验 `移动 ≤ 安全 ≤ 工作`)→ **⑥「生成打孔 G-code(GRBL)」**
  下载 `*_tape.gcode`(点击时会先应用⑤的值, 并弹出统计提示);
- CLI: `from server.gcode import params_from, tape_to_gcode`(或 `tools/make_preflight_gcode.py`
  生成预校验文件 —— 它读 `data/project.json` 的 `z_params`, 与 GUI ⑤ 选定的值一致)。

## 6. 上机前校验流程(建议顺序)

1. **干跑坐标**(抬高 Z 或断开冲针电气),两个文件都由 `tools/make_preflight_gcode.py` 按**当前工程纸带**生成:
   - `out/canon_preflight_edges.gcode`:在 Y=0 同一横线上打 `col0`(X=6.25)与 `col29`(X=63.75)。
     量纸带左右留白是否各 6.25mm,确认**X 行程到得了两端、X+ 确实是向右**。
   - `out/canon_preflight_2holes.gcode`:**时间上第一个音符**(row0/col5 → X≈16.164, Y=0)与
     **最后一个音符**(row5237/col28 → X≈61.767, Y≈3206.3)。确认 **Y+ 确实是向前**、且末端位置正确。
2. **确认 Y0 语义**:本纸带第一个音符恰在 Y=0;确认装夹时 Y0 就是纸带起点,而不是限位/未装带位置。
3. **确认纸带够长**:本曲冲孔段 3206mm + 尾部 100mm ≈ **3.31 m**。
   若启用了软限位(`$20`=1),须先确认 `$131`(Y 行程上限)≥ 3310mm。
   当前 `$20`=0(**软限位关闭**),`$130`–`$132` 不参与判断,故此项要以**实际机械行程**为准(见 §7.3)。
4. 再跑整曲 `canon_full.gcode`(文件名沿用早期卡农曲的命名,内容已是当前工程纸带);
   长文件建议先空跑一小段验证送带速度与定位。
5. 需要重新生成预校验文件时,直接跑 `python tools\make_preflight_gcode.py` —— 它读 `data/project.json`,
   所以生成的孔位与 GUI ⑤ 选定的 Z 高度都与当前工程一致。

> 📏 **纸带用量**:`纸带长度 = 时长 × feed_mm_s × k`,默认 `feed_mm_s = 16` ⇒ 每分钟音乐约 0.96 m(k=1)。
> **`k` 是 Y 轴拉伸系数**:BPM 越高则 `mm_per_step` 越小、孔距越密,密到音梳来不及复位时
> 就得把 Y 放大 k 倍,同时把八音盒走带速度也调快 k 倍,声音时长才不变。
> 所以**快曲子会比"时长×16"长出不少**:本机那份 Marshmello《Alone》(bpm=142、每步 0.4225mm)
> Y 拉伸 150%、八音盒设 260 BPM 播放,纸带冲孔段 5.1m → **7.67m**(加尾部 7749mm),
> 而音乐只有约 3 分半。
> 因此 30 秒以上的整曲通常就要 1 米以上,买料按"整卷能打几首"算更划算
> (选型、价格与实测平替见 [README「纸带」一节](../README.md#纸带选什么买多少))。

### 7.1 逐轴参数

| 设置 | 含义 | 本机实测 | 程序默认 | 判定 |
|---|---|---|---|---|
| `$100` | X steps/mm(**走 1mm 需多少脉冲**) | **403.000** | — | 标定值,换机械/细分须重测 |
| `$101` | Y steps/mm | **53.000** | — | 同上 |
| `$102` | Z steps/mm | **400.000** | — | 同上 |
| `$110` | X 最大速率 (mm/min) | **2500.000** | `xy_feed` 3000 | ⚠️ **超限**(见 7.2) |
| `$111` | Y 最大速率 (mm/min) | **2500.000** | `y_feed_mm_min` 1000 | ✅ 送带需 ≥1000,满足 |
| `$112` | Z 最大速率 (mm/min) | **2500.000** | `z_feed` 2000 | ✅ 需 ≥2000,满足 |
| `$120` | X 加速度 (mm/s²) | **2000.000** | — | 不影响本程序(X 空移速率已受限) |
| `$121` | Y 加速度 (mm/s²) | **2000.000** | — | 送带 16.7mm/s,加速距离仅 0.07mm |
| `$122` | Z 加速度 (mm/s²) | **400.000** | — | 由它主导冲孔节拍(见 §8) |
| `$130/$131/$132` | X/Y/Z 行程上限 | 200.000 | — | **当前不生效**(见 7.3) |

其余:`$0`=2µs(脉冲宽度)、`$1`=25(步进使能延迟)、`$2`–`$6`=0(不反转任何信号)、
`$10`=0、`$11`=0.010、`$12`=0.002、`$20`–`$27`=0(**软限位/硬限位/回零全部关闭**)、
`$30`=1000、`$31`=0、`$32`=0,无 `$35`。程序内已含 `G21`(mm)/`G90`(绝对)/`G94`(mm/min)。

### 7.2 ⚠️ 已知不一致:`xy_feed` 超过 X 轴上限

`server/gcode.py` 的 `MachineParams.xy_feed` 默认 **3000 mm/min**,而本机 `$110`(X 最大速率)
只有 **2500**。GRBL 会自行按 `$110` 限速,所以**不会出错,但 G-code 注释里的 X 空移耗时会被低估约 17%**
(按 3000 算,实际按 2500 走)。

⇒ 与本机匹配的做法:把 `xy_feed` 设为 **≤2500**。

> 因此 [§8 末尾](#8-耗时模型与实测)所列优化建议中的
> "**提高 `xy_feed`(3000 → 12000 mm/min)**" **在本机上不可行** —— 远超 `$110`/`$111` 的 2500 上限。
> 想缩短空移只能从路径规划入手(见 §4 的"每行从最近端进入"),不要提高进给。

### 7.3 `$130`–`$132` 当前不生效

三者均为 200mm,但 `$20`(软限位)、`$21`(硬限位)、`$22`(回零)都是 **0(关闭)**,
因此这三项**不参与任何限位判断**,不影响实际可打纸带长度。

⇒ 所以 §6 第 3 步"确认 `$131` ≥ 5690mm 纸带总长"**仅在启用软限位(`$20`=1)后才成立**。
是否启用按你的机械与安全需求决定:启用后 `$130`–`$132` 必须按实际行程重填,否则会误报警。

**脉冲频率上限**:GRBL(Arduino)常见上限约 30kHz。若 Z 为 100 steps/mm、速度 2000mm/min(33mm/s)
⇒ 约 3.3kHz,没问题;但若把 Z 速度设成 2000mm/s 就会到 200kHz,**超出控制器能力**。
本机 Z 为 `$102`=400 steps/mm,同样速度下脉冲率是 100 steps/mm 的 4 倍,留意为宜。

**长文件流控(当前未实现,见路线图)**:本曲 16000+ 行,上位机直连串口时必须流式发送
(GRBL 接收缓冲约 127 字节,按 `ok` 应答推进;`?` 查询状态;`!`/`~` 进给保持/恢复;`Ctrl-X` 软复位)。

## 8. 耗时模型与实测

单孔时间 ≈ `(2 × Z行程) / z_feed` + `dwell_s`;总时长 ≈ 送带 + X 空移 + Z 冲程 + 停留。

本工程当前纸带(MIDI 导入 `Shelter.mid`,经 ③ 量化:**1432 孔 / 718 个有孔行 / bpm=98 × 16格每拍**),
按**工程当前 `z_params` = 工作 10 / 安全 6 / 移动 0**(⇒ Z 行程 4mm)由 `POST /api/gcode` 实算:

```
step_seconds = 60 / (98 × 16) = 0.038265 s
mm_per_step  = 0.038265 × 16  = 0.6122 mm
纸带冲孔段   = 5237 步 × 0.6122 = 3206 mm(末步在 row 5237)
```

| 项目 | 时间 |
|---|---|
| 送带(3306mm @1000mm/min,含尾部 100mm) | 198.4 s |
| X 空移(1432 孔 / 3000mm/min) | 384.3 s |
| Z 冲程(4mm×2 @2000mm/min × 1432 孔) | 343.7 s |
| 冲孔停留(0.1s × 1432 孔) | 143.2 s |
| **合计** | **约 17.8 分钟**(1069.6 s) |

> Z 冲程这一项直接由行程决定:行程 4mm ⇒ 0.24s/孔;若把 `z_safe` 改成默认的 4(行程 6mm)
> ⇒ 0.36s/孔,全曲 Z 冲程就从 344s 涨到 516s,总时长约 20.7 分钟。**这是"安全高度"最直接的代价。**

> 纸带长度与曲目时长:本曲音乐时长 = 5237 × 0.038265 ≈ **200 s**,纸带冲孔段 3206mm,
> 两者之比正好是 `feed_mm_s`(16 mm/s)—— 即 §3 的"纸带长度 = 时长 × feed_mm_s"。
> 估算任何曲子的用料只要这一条,见 [README「纸带」一节](../README.md#纸带选什么买多少)。

> ⚠️ 若把 Z 速度写得很高(如 F120000),**实际不会线性变快**:
> 4~6mm 行程内达到该速度需要极高加速度(`v²=2as`),步进机达不到,GRBL 会按 `$122` 自行限速。
> 想真正缩短节拍,应按实机 `$122` 与实测单孔 Z 用时重算。

**进一步优化的安全选项**(以下按本曲实算):
- `xy_feed` 当前 3000 超过本机 `$110`/`$111` 上限 2500(见 §7.2):按 2500 实走,X 空移是 461s 而不是 384s。
  把它改回 2500 **不是优化,只是让注释里的耗时不再偏乐观**。
- 降低 `dwell_s`(0.1 → 0.03):省约 100s;**只影响压住时间,改前确认冲孔质量**。
